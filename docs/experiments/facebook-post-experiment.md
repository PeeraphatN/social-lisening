# การทดลองดึงโพสต์ Facebook ด้วยเครื่องมือฟรี

สถานะล่าสุด 7 ตุลาคม 2026: **ทดลองครบ 3 รอบ ผ่าน 15/15 ครั้ง** ข้อความดิบทุกครั้งตรงข้อมูลอ้างอิงที่ผู้ใช้ตรวจแล้วทั้ง 5 โพสต์ เว้นอย่างน้อย 10 นาทีระหว่างรอบ และไฟล์รวมมี 5 โพสต์ไม่ซ้ำ ดู [รายงานผลรันซ้ำ](facebook-post-repeat-results.md) ข้อสรุปจำกัดอยู่ที่การดึงข้อความจากลิงก์ชุดนี้ ยังไม่ใช่การค้นหาโพสต์ทั่ว Facebook

วันที่: 6 ตุลาคม 2026

## 1. เป้าหมายและสมมติฐาน

พิสูจน์ว่าโปรแกรมบนเครื่องบริษัทสามารถอ่านข้อความจากโพสต์ Facebook สาธารณะตามลิงก์ที่กำหนด และบันทึกข้อความภาษาไทยได้ถูกต้อง ก่อนลงทุนพัฒนาระบบติดตาม TKC

สมมติฐานตั้งต้น:

1. ใช้ Windows และคอมพิวเตอร์/อินเทอร์เน็ตที่มีอยู่แล้ว
2. คำว่า “ฟรี 100%” หมายถึงไม่มีค่าสมาชิก ค่า API ค่า proxy หรือค่าบริการ cloud เพิ่มเติม เครื่องมือทั้งหมดทำงานในเครื่อง ค่าไฟ อินเทอร์เน็ต และเวลาทำงานยังมีอยู่
3. เริ่มจากลิงก์โพสต์ที่ตรวจด้วยมือได้ 5 ลิงก์ ไม่ใช่การรับประกันค้นหาโพสต์เกี่ยวกับบริษัททั่ว Facebook
4. เก็บข้อความโพสต์ก่อน ยังไม่รวมความคิดเห็น การอ่านข้อความในรูป วิดีโอ หรือ sentiment
5. ใช้ข้อมูลสาธารณะที่มีสิทธิ์หรือเงื่อนไขรองรับการเก็บ ในรอบแรกไม่เพิ่มเครื่องมือหลบข้อจำกัดของเว็บไซต์

คำถามการทดลอง: “จากโพสต์สาธารณะ 5 ลิงก์ที่คนเปิดอ่านได้ โปรแกรมดึงข้อความที่เจ้าของโพสต์เขียนได้ครบกี่โพสต์ และรันซ้ำได้ผลถูกต้องเหมือนเดิมหรือไม่?”

ผลทดลองขนาดเล็กนี้ใช้ตัดสินใจว่าจะพัฒนาต่อ ไม่ใช้สรุปว่าเก็บข้อมูล Facebook ได้ครบหรือรองรับการใช้งานต่อเนื่องระดับบริษัทแล้ว

## 2. เครื่องมือและวิธีที่เลือก

ใช้ **Python + Playwright + Chromium** บนเครื่อง Windows ส่งออกเป็น JSON และ CSV ไม่ต้องมีฐานข้อมูลหรือเว็บ dashboard ในรอบนี้

Playwright เป็นเครื่องมือควบคุมเบราว์เซอร์ สามารถเปิดหน้าเว็บและอ่านเนื้อหาที่หน้าแสดงจริง รองรับการเปิดเบราว์เซอร์ให้เห็นหน้าต่างตาม [เอกสารผู้พัฒนา](https://playwright.dev/python/docs/library) และเผยแพร่ภายใต้ [Apache-2.0](https://github.com/microsoft/playwright-python/blob/main/LICENSE)

เหตุผลที่เลือก: ต้องตรวจการโหลดหน้าและข้อความปัจจุบันด้วยตาได้ การทดลองจะเขียนตัวอ่าน DOM เฉพาะโพสต์ที่พบจริง ไม่สมมติว่า selector Facebook จากบทความเก่ายังทำงาน ไม่เริ่มจาก facebook-scraper เก่าที่มี [รายงานดึงโพสต์ไม่ได้](https://github.com/kevinzg/facebook-scraper/issues/1130)

วิธีนี้ยังต้องเขียนตัวดึงข้อความเอง Playwright ไม่ใช่ตัวดึงโพสต์ Facebook สำเร็จรูป และยังไม่มีหลักฐานว่าลิงก์ตัวอย่างจะดึงสำเร็จ

## 3. ชุดตัวอย่างและข้อมูลอ้างอิง

เลือก 5 โพสต์จากอย่างน้อย 2 เพจสาธารณะ โดยมีความเกี่ยวข้องกับ TKC หรือโครงการที่เกี่ยวข้องเมื่อหาได้ หากจำนวนไม่พอ ใช้โพสต์ข่าวภาษาไทยอื่นเป็นตัวควบคุมทางเทคนิค และระบุว่าเป็นตัวควบคุม

| ตัวอย่าง | ลักษณะ | สิ่งที่ตรวจ |
| --- | --- | --- |
| P01 | ข้อความภาษาไทยสั้น | อ่านเนื้อหาหลักถูกต้อง |
| P02 | ข้อความภาษาไทยยาว มี “ดูเพิ่มเติม” | ขยายข้อความและเก็บครบ |
| P03 | โพสต์มีรูปและคำบรรยาย | เก็บเฉพาะคำบรรยาย ไม่ใช้ OCR |
| P04 | โพสต์มีลิงก์ข่าวและข้อความของผู้โพสต์ | ไม่สับสนกับพาดหัวใน link preview |
| P05 | ข้อความไทย/อังกฤษหรือ emoji | อักขระไม่เสียหาย |

ตัวอย่างต้องเป็นลิงก์ไม่ซ้ำ ถ้าโพสต์แก้ไขระหว่างการทดลอง ให้บันทึกการเปลี่ยนแปลง ไม่ใช้ข้อมูลอ้างอิงเดิมตัดสินว่าโปรแกรมผิด

ก่อนรัน ตรวจแต่ละลิงก์ด้วยมือ แล้วบันทึกข้อความที่มองเห็นหลังขยาย “ดูเพิ่มเติม”, ชื่อเพจ, ลิงก์ปลายทาง, เวลาที่หน้าแสดง, เวลาที่ตรวจ และภาพหน้าจอเฉพาะส่วนโพสต์ลงโฟลเดอร์ผลทดลอง

ข้อมูลนี้เป็นคำตอบอ้างอิงสำหรับเปรียบเทียบ ไม่ใช่ข้อมูลที่ตัวดึงโปรแกรมสร้างเอง หากอ่านด้วยมือไม่ได้ ให้บันทึกเป็นตัวอย่างปัญหาการเข้าถึง และเลือกตัวอย่างที่อ่านได้มาทดแทนสำหรับชุดหลัก

รอบแรกเลือกโพสต์ต้นฉบับ ไม่ใช้โพสต์แชร์ซ้อนหลายชั้น เพื่อลดความกำกวมว่าใครเป็นผู้เขียนและข้อความส่วนใดเป็นเป้าหมาย

ลิงก์ Facebook ที่ข่าวอ้างไว้ใน [งานค้นคว้า TKC](../research/tkc-public-discussion.md) เป็นเพียงตัวตั้งต้น ต้องตรวจด้วยมือก่อนนำเข้าชุดทดลอง

## 4. รูปแบบข้อมูล

เก็บหนึ่ง record ต่อหนึ่งโพสต์ต่อหนึ่งรอบ:

| กลุ่ม | fields | กติกา |
| --- | --- | --- |
| ระบุต้นทาง | `sample_id`, `input_url`, `resolved_url`, `post_id` | ใช้ ID เมื่อดึงได้จริง ถ้าไม่ได้ให้ null ไม่เดา |
| ผู้เผยแพร่และเนื้อหา | `publisher`, `text` | ข้อความที่เจ้าของโพสต์เขียน ไม่รวมความคิดเห็น เมนู หรือ link preview |
| เวลา | `displayed_time_raw`, `published_at`, `collected_at` | เก็บเวลาที่หน้าแสดงตามจริง; ถ้าระบุเวลาตีพิมพ์แน่นอนไม่ได้ให้ null; เวลาที่เก็บใช้ ISO 8601 พร้อม timezone |
| ผลรอบทดลอง | `run_id`, `status`, `duration_seconds`, `error_reason` | แยก ok, incomplete, login_required, blocked, unavailable, timeout และ unsupported |
| หลักฐานตรวจ | `evidence_path`, `manual_match` | ภาพส่วนโพสต์และผลเปรียบเทียบกับข้อมูลอ้างอิง |

ค่า `status=ok` ต้องได้ข้อความโพสต์เต็มที่ตรวจเทียบแล้ว ไม่ใช่เพียงได้ HTTP 200 หรือข้อความทั้งหน้าที่ปนเมนูและความคิดเห็น

การอ่านโพสต์สำเร็จแต่ข้อความไม่ครบต้องใช้ `incomplete` เวลาไม่ทราบต้องเป็น null ไม่ใช้ `collected_at` แทน `published_at`

CSV ใช้ UTF-8 with BOM สำหรับเปิดข้อความไทยใน Excel บน Windows JSON ใช้ UTF-8 เก็บข้อความดิบที่อ่านได้ไว้ และสร้างค่าที่ปรับเฉพาะช่องว่าง/บรรทัดใหม่สำหรับการเปรียบเทียบ โดยไม่ตัด emoji หรือคำไทย

ตัวอย่างรูปแบบข้อมูลสมมติ ไม่ใช่ผลดึงจริง:

```json
{
  "sample_id": "P01",
  "input_url": "<ลิงก์โพสต์ที่ตรวจแล้ว>",
  "publisher": "<ชื่อเพจที่หน้าแสดง>",
  "text": "<ข้อความเต็มของเจ้าของโพสต์>",
  "published_at": null,
  "displayed_time_raw": "<ข้อความเวลาที่หน้าแสดง>",
  "status": "incomplete",
  "error_reason": "example_only"
}
```

## 5. ขั้นตอนรันและเกณฑ์ตัดสิน

1. **เตรียมชุดอ้างอิง:** ตรวจ 5 ลิงก์และบันทึกข้อความ/ภาพ ใช้ประมาณ 15-25 นาที
2. **ตรวจหน้าแรก:** เปิด P01 ในเบราว์เซอร์ที่ควบคุมโดยโปรแกรม ตรวจตำแหน่งข้อมูลจริงก่อนออกแบบ selector อย่าใช้ข้อความทั้งหน้าเป็นผลโพสต์
3. **รันชุดหลัก:** เปิดทีละลิงก์ในเบราว์เซอร์เดียว จำกัดไม่เกิน 60 วินาทีต่อโพสต์ ไม่ retry อัตโนมัติในรอบแรก ปัญหาการปิดกั้นหรือ CAPTCHA ให้หยุดรอบและบันทึกเหตุผล
4. **รันซ้ำ:** ใช้ชุดเดิมรวม 3 รอบ เว้นประมาณ 10 นาทีระหว่างรอบ โดยไม่ปรับโค้ดระหว่างรอบเพื่อไม่ให้เปลี่ยนตัวแปรทดลอง ถ้าปรับโค้ดให้นับเป็นการทดลองเวอร์ชันใหม่
5. **ตรวจผล:** เทียบกับคำตอบอ้างอิงทีละโพสต์ ตรวจ UTF-8 และทดลองนำเข้าผลรอบเดียวซ้ำ เพื่อยืนยันการแยกข้อมูลโพสต์ไม่ซ้ำในไฟล์รวม

ถ้าชุดหลักทำได้ครบ จะมีการเปิดสูงสุด 15 ครั้งตามแผน ไม่รันเบื้องหลังต่อเนื่อง จังหวะเว้นรอบเป็นเพียงการออกแบบโหลดทดลอง ไม่ได้เป็นข้อยืนยันว่า Facebook อนุญาตหรือจะไม่จำกัดคำขอ

| เกณฑ์ | ผ่านเพื่อพัฒนาต่อ |
| --- | --- |
| ข้อความเต็มและชื่อเพจถูกต้อง | อย่างน้อย 4 จาก 5 โพสต์ในแต่ละรอบ และต้องตรงกับข้อมูลอ้างอิงล่าสุด |
| ตัวอย่างสำคัญ | P02 ข้อความยาว และ P05 อักขระไทย/emoji ต้องผ่านทุกครั้ง |
| รายการที่ระบบรายงานว่า ok | ไม่มีข้อความผิดโพสต์หรือปนความคิดเห็น/เมนูแม้แต่รายการเดียว |
| ความโปร่งใสของความล้มเหลว | ทุกลิงก์ที่ลองมี record สถานะ หรือระบุ `not_attempted` หากหยุดรอบก่อน; ไม่ตีความล้มเหลวว่าไม่มีโพสต์ |
| ไฟล์รวม | หนึ่งรายการต่อ stable post ID หรือลิงก์ปลายทางที่ตรวจแล้ว; การรันซ้ำไม่เพิ่มสำเนาของโพสต์เดียวกัน |

นับตัวหารเป็นชุดที่กำหนดไว้ก่อนรัน 5 โพสต์เหมือนเดิม ห้ามตัดลิงก์ที่โปรแกรมดึงไม่ได้ออกเพื่อทำให้เปอร์เซ็นต์ดีขึ้น

ถ้าผ่าน: ทดลองการค้นพบลิงก์โพสต์จาก 2 เพจหรือ keyword search เป็นงานถัดไป พร้อมชุดตรวจความครอบคลุมแยกต่างหาก

ถ้าไม่ผ่าน: รายงานสาเหตุว่าเป็นปัญหาเข้าถึงหน้า, ข้อความไม่โหลด, selector ผิด, หรือรูปแบบโพสต์ไม่รองรับ ก่อนตัดสินใจแก้หรือเปลี่ยนแนวทาง ไม่เพิ่มบริการเสียเงินเพื่อให้การทดลองนี้ผ่าน

## 6. การล็อกอินและขอบเขต

เริ่มตรวจแบบไม่ล็อกอินก่อน หากได้ `login_required` ให้รายงานผลนั้นอย่างตรงไปตรงมา หากต้องการทดสอบแบบผู้ใช้ล็อกอิน จะเป็นรอบทดลองแยก ใช้การล็อกอินด้วยมือในเบราว์เซอร์ทดลอง และนำผลมาแยกตามเงื่อนไข ไม่รวมกับคะแนนรอบไม่ล็อกอิน

Playwright มีการเก็บ authenticated state ตาม [เอกสาร authentication](https://playwright.dev/python/docs/auth) แต่ไฟล์ดังกล่าวมีข้อมูลที่ใช้แทนการล็อกอินได้ ต้องอยู่ในเครื่องและถูกกันจาก Git ไม่ส่งรหัสผ่านหรือ session state ในรายงาน

Always: เปิดทีละหน้า, ตรวจด้วยข้อมูลอ้างอิง, บันทึกความล้มเหลว, เก็บผลในเครื่อง, ระบุความเกี่ยวข้องกับบริษัทตามหลักฐาน

Ask first: เปลี่ยนไปเก็บพื้นที่ไม่สาธารณะ, ใช้บริการเสียเงิน, ส่งข้อมูลหรือ credentials ออกนอกเครื่อง หรือขยายไปเป็นระบบรันต่อเนื่อง

Never: bypass CAPTCHA หรือข้อจำกัดการเข้าถึง, หมุนบัญชีเพื่อหลบการปิดกั้น, เก็บรหัสผ่านใน source, หรืออ้างว่าครอบคลุม Facebook ทั้งหมดจากการทดลอง 5 โพสต์

การอนุญาตใช้ตัวโปรแกรมเป็นคนละเรื่องกับเงื่อนไขใช้ข้อมูล Facebook ดู [ประกาศ Meta เรื่อง unauthorized scraping](https://about.fb.com/news/2022/07/actions-against-scraping-for-hire/) การทดลองทางเทคนิคนี้ไม่ใช่หลักฐานว่าได้รับอนุญาตให้เก็บข้อมูลในทุกกรณี

## 7. โครงสร้างและคำสั่งสำหรับขั้นพัฒนา

เป็นโครงสร้างเป้าหมายของชุดทดลองเต็ม ปัจจุบันมี `probe_post.py`, `inspect_browser.py` และผล P01 แล้ว แต่ยังไม่มี `collect_posts.py` สำหรับรันชุด 5 โพสต์ตาม CLI ด้านล่าง:

```text
experiments/facebook_posts/
  collect_posts.py         # ตัวดึงสำหรับการทดลอง
  inputs.csv               # 5 ลิงก์ที่ตรวจแล้ว
  reference.json          # คำตอบอ้างอิงที่บันทึกด้วยมือ
  .auth/                   # session เฉพาะเครื่อง ถ้าทดลองเงื่อนไขล็อกอิน
  runs/<run_id>/           # ผลแต่ละรอบและภาพหลักฐาน
  posts.csv                # ไฟล์รวมที่ตัดรายการซ้ำ
```

สไตล์โค้ด: Python snake_case, synchronous Playwright สำหรับลำดับทีละหน้า, ฟังก์ชันสั้นตามงานเปิดหน้า/อ่านโพสต์/บันทึกผล ใช้ csv/json จาก standard library ก่อนเพิ่ม dependencies อื่น

คำสั่งเตรียม environment สำหรับชุดเต็ม ปัจจุบันติดตั้ง environment เฉพาะตัวทดลองไว้ใน `experiments/facebook_posts/.venv` และ browser ใน `.playwright` แล้ว:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install playwright
.\.venv\Scripts\python.exe -m playwright install chromium
```

คำสั่งตัว collector หลังเขียนไฟล์จริงแล้วเท่านั้น:

```powershell
.\.venv\Scripts\python.exe experiments/facebook_posts/collect_posts.py --input experiments/facebook_posts/inputs.csv --reference experiments/facebook_posts/reference.json --run-id trial-01
```

ล็อกเวอร์ชัน dependencies ที่ทดลองผ่านไว้เมื่อทำจริง และกัน `.venv/`, `.auth/`, session data และผลที่มีข้อมูลจริงจาก Git ตามตำแหน่งใช้งาน การเขียนตัว collector ใช้ประมาณ 2-4 ชั่วโมงสำหรับนักพัฒนา หากเปิดหน้าเป้าหมายได้ตามปกติ; ตรวจและรัน 3 รอบอีกประมาณ 45-75 นาที เวลานี้เป็นประมาณการ ยังไม่ทราบรูปแบบหน้าเป้าหมายจริง

## สิ่งที่ยังต้องมีเพื่อเริ่มลงมือ

ผู้ใช้ตรวจข้อความ P01–P05 ผ่านแล้ว และชุดรันซ้ำผ่านทั้ง 3 รอบ งานทดลองดึงข้อความจากชุดลิงก์นี้เสร็จแล้ว กรณีแยกพาดหัวข่าวในกล่อง link preview ยังไม่ถูกทดสอบ เพราะ P04 จริงเป็นโพสต์มีรูปและ URL ในข้อความ ส่วนชื่อผู้เผยแพร่ของ P02 และ P05 ยังเป็นชื่อที่ตรวจด้วยมือ ในการรันซ้ำตรวจเพียงว่าชื่อที่รู้แล้วปรากฏในส่วนหัวของหน้า ไม่ใช่ตัวดึงชื่อผู้เขียนทั่วไป และ P05 ใช้ URL เจาะจงโพสต์แทนลิงก์หน้ากลุ่ม ขั้นถัดไปของบริการคือออกแบบการค้นพบโพสต์เกี่ยวกับ TKC ซึ่งเป็นขอบเขตใหม่แยกจากผลทดลองนี้
